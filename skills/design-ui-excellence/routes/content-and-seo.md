## Define the content job

For each page or interface surface, establish:

- intended audience
- user question or task
- awareness and entry source
- business purpose
- primary action
- required proof
- search intent when relevant
- lifecycle and owner
- success signal

A page without a distinct job should be merged, redirected, or removed rather than filled.

## Build a message hierarchy

Create:

1. position or core promise
2. audience relevance
3. mechanism or explanation
4. benefits and outcomes
5. proof
6. objections and constraints
7. action

Keep the same vocabulary across navigation, page copy, forms, product UI, and confirmation states. Variation is useful in editorial voice, not in the names of the same objects and actions.

## Write for comprehension

- Lead with what changes for the reader.
- Use concrete nouns, verbs, mechanisms, and constraints.
- Prefer specific evidence to adjectives.
- Keep one idea per paragraph or UI message.
- Use headings that reveal content rather than decorate it.
- Make links understandable out of context.
- Label buttons with the action or destination.
- Write errors as recovery instructions.
- Keep serious moments calm and explicit.
- Avoid filler, empty superlatives, insider language, and generic AI phrasing.

Do not ban ordinary words mechanically. Reject a phrase because it is vague, false, repetitive, off-voice, or unhelpful.

## Plan search visibility intentionally

For pages intended to be discovered:

- map one primary intent and closely related supporting questions
- answer the query directly before expanding
- use a descriptive title, primary heading, summary, and URL
- establish internal links based on user journeys and topic relationships
- provide original evidence, examples, comparisons, or expertise
- make authorship, ownership, and update expectations clear when relevant
- use structured data only when the visible content and entity facts support it

For campaign-only, private, duplicate, or temporary pages, choose indexing intentionally rather than by default.

Verify current platform-specific SEO requirements from primary documentation when exact behavior matters. Do not rely on remembered snippets or promise rankings.

## Interface content

Cover:

- labels and helper text
- validation and errors
- empty states
- loading and completion
- destructive actions
- permissions and unavailable states
- notifications
- onboarding and progressive disclosure

Place guidance where the user needs it. Do not use placeholders as labels or hide recovery in generic toasts.

## Content-system delivery

For larger work, provide:

- page inventory
- message map
- voice and terminology rules
- content model
- metadata pattern
- linking strategy
- example copy
- localization considerations
- ownership and update cadence
- measurement plan

Validate with real lengths, mobile wrapping, text expansion, screen-reader navigation, and representative translated strings.
