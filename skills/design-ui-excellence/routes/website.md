# Website Route

Use this route for multi-page marketing sites, homepages, company sites, portfolios, documentation fronts, ecommerce surfaces, and existing-site redesigns.

Use the landing-page route instead when one offer, one audience, and one conversion action dominate the page.

## 1. Classify the change

Choose one:

- **Greenfield** — establish a new system from the brief.
- **Extension** — add pages or sections that should feel native to the existing site.
- **Preserve redesign** — improve hierarchy, clarity, responsiveness, and craft while retaining brand recognition and familiar structure.
- **Overhaul** — replace the visual or structural system because the user explicitly requested a new direction.

For existing sites, inventory the current vocabulary before changing it: tokens, type, spacing, surfaces, layout, navigation, components, motion, content model, assets, and protected behavior.

## 2. Define the site system

For every page, state:

- page job
- primary audience and visitor state
- primary action
- information users must leave with
- proof or evidence required
- relationship to other pages
- search or campaign intent when relevant

Design the navigation and content architecture from those page jobs, not from a generic company-site sitemap.

## 3. Establish direction

Create a concise design read:

- experience mode: persuade, operate, read, or experience
- visual thesis
- brand fidelity
- information density
- visual variance
- motion intensity
- art-direction dependence

Translate it into a style contract. Reuse existing tokens when healthy; do not create a parallel system just to make the redesign feel new.

For broad builds, implement one representative vertical slice first: real content, real assets, responsive behavior, and the central interaction. Use it to validate the system before duplicating it across every page. In autonomous work, run the critique internally and continue; do not force a user checkpoint unless the decision is genuinely unresolved.

## 4. Compose pages as arguments or tasks

Marketing pages need a clear narrative, but not identical section stacks. Assign each section a job and vary form according to content:

- focused product visual
- comparison
- annotated screenshot
- diagram or process
- proof block
- editorial explanation
- data or result
- objection handling
- action

Avoid repeating the same eyebrow, heading, paragraph, and card grid for every section.

Commerce pages must support evaluation and purchase confidence: product facts, availability, variants, shipping/returns, trust, comparison, and recovery from errors. Do not hide critical purchase information behind visual theater.

## 5. Build with real constraints

- Use real draft copy and representative content lengths.
- Preserve official logos, screenshots, and product imagery.
- Define image behavior, cropping, and aspect ratios.
- Design mobile hierarchy deliberately; do not merely stack desktop columns.
- Include navigation, footer, legal and privacy surfaces required by the project.
- Cover loading, empty, error, disabled, and unavailable states where relevant.
- Make forms, filters, menus, media, and overlays keyboard-operable.
- Keep the implementation native to the existing framework and component stack.

## 6. Ship the whole surface

Before delivery, verify:

- every page has a distinct job and clear next step
- navigation and wayfinding work
- titles, descriptions, canonical/indexing choices, social metadata, and structured data are intentional
- no fabricated proof or placeholder production content remains
- responsive behavior works with short, long, missing, and translated content
- focus, keyboard, reduced motion, zoom, and contrast are handled
- assets load efficiently and layout remains stable
- no dead links, dead controls, clipped content, or accidental horizontal scrolling
- the rendered result still follows the style contract
