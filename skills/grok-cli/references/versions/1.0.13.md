## Headless tool filtering

- Use `run_terminal_command` in `--tools` when shell access is required. The
  active `grok-build-plan` profile exposed this name. The bundled headless
  chapter's `run_terminal_cmd` example is not the supported contract here.
- With a narrow `--tools` list, intentional subagent access requires `Agent`
  or `Agent(type,...)`. Omitting `--no-subagents` alone is insufficient.
  `spawn_subagent` is the model-facing tool name, not the operator directive.
- Verify effective tools before a long call through
  `available_commands.tools` in `streaming-json` or the `system`/`init` tool
  list in `streaming-messages-json`. This creates a remote session and may use
  paid model capacity, so do it only within the caller's authority.

Example with unrestricted subagent types:

```bash
--tools "read_file,grep,list_dir,run_terminal_command,Agent"
```

Also ensure subagents remain enabled in the selected environment, agent, and
configuration. Inspect the selected child-agent definition before relying on
its capability boundary.

## Permission cancellation

Under `--permission-mode dontAsk`, an unmatched shell request was observed as
`permission_cancelled` and ended the current prompt. It did not merely skip the
command. Preflight every segment of required compound commands against exact
`Bash(...)` rules, and treat a cancelled invocation as incomplete even when it
already emitted partial output.
