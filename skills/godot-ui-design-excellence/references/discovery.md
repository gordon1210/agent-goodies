# Discovery: establish constraints without redesigning the world

## Read before asking

Inspect project instructions, `project.godot`, the relevant `.tscn`, `.tres` and
scripts, current screenshots, font and icon assets, localization resources, and
existing UI conventions. Read the actual engine executable's version when execution
is permitted; a filename or a repository tag alone is not proof. Distinguish
GDScript and C# projects. Preserve the established language and architecture.

Record five compact facts: player task; screen/context; target devices and viewing
distance; existing visual identity; current defect or desired outcome. Resolve
engine version, renderer, UI scale policy, input devices, and available capture
workflow from the repository. Do not turn a button repair into a brand workshop.

## Questions that genuinely change the result

For an undefined new interface, ask which screen and gameplay decisions are in
scope, what reference qualities matter, what devices must work, and whether a
visual direction already exists. "Like Expedition 33" could mean typography,
painterly graphics, battle composition, or transitions; do not silently assume all.
Group the remaining questions into one concise request. With explicit creative
delegation, choose and record a direction instead of repeatedly seeking approval.

For incomplete but actionable work, separate reversible proposals from changes
that need a product decision. Use clearly labeled fixture data; do not invent
requirements and later report them as the user's specification.

## Capability contract

| Available capability | Honest output |
|---|---|
| Files only | Design contract, implementation, static checks; visual quality unverified |
| Screenshots / image inspection | Static composition and state review; motion unverified |
| Running scene + input + captures | Interactive, visual, and layout verification on that environment |
| Recording / frame inspection | Temporal review; timings only if actually measured |
| Image/DCC tools | Authored asset workflow within permissions; not automatically production-ready |

A text skill does not install a renderer, grant repository permissions, or give an
agent sight. Reuse already approved tooling. Ask before adding paid services,
plugins, SDKs, or network uploads. Keep sensitive project images local unless
external sharing is authorized.

## Working record

Use an existing project documentation location, or create a small `ui/design/`
folder when none exists. Store a brief, one screen contract, reference pointers,
source asset manifest, and review evidence. Record the exact scene and scenario
needed to reproduce a screenshot. Do not commit generated imports or external
screenshots automatically; follow repository policy and rights restrictions.

The baseline documentation used to author this package is Godot 4.7. It is not a
minimum version requirement. Confirm every version-sensitive property against the
installed release; use an equivalent supported pattern instead of migrating.
